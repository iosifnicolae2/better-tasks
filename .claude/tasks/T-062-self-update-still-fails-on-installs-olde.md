Facts found by the lead:
- Installed: better-tasks 0.11.3 (~/.claude/plugins/installed_plugins.json, user scope).
- T-053's fix shipped in v0.11.4. So the updater that ran was 0.11.3's old code, which re-adds the marketplace pinned to the tag.
- The project's .claude/settings.json pins extraKnownMarketplaces.better-tasks to ref v0.10.8. The user's ~/.claude/settings.json declares the same repo with no ref.
- Result: an install older than 0.11.4 can never self-update to the version that fixes self-update.

Done:
1. This Mac gets to v0.11.7 (or the latest) and the project pin moves with it. Use the CLI the way the fixed updater would, and verify that `claude plugin list` shows the new version.
2. Check that the fixed updater (v0.11.7 code) really updates from inside this project with this exact setup: user declaration plus a project pin. Test it in an isolated CLAUDE_CONFIG_DIR, not live.
3. Give stuck users a one-time way out. A line in the README and in the next release notes with the exact command(s) is enough. If there's a way to unstick them without the user's action, prefer it.
